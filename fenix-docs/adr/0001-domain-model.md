# ADR 0001: Domain Model (The Fénix Universe)

## Status
Accepted

## Context
Fénix manages an entire software factory. Without a strict domain model, the system becomes a chaotic collection of scripts. We must define the universal entities that govern Fénix, their properties, and their strict hierarchy. Fénix is not a single-project tool; it is a multi-organization, multi-product, and multi-model Operating System.

## Decision
The core entities of the Fénix Domain Model are defined in a strict macroscopic to microscopic hierarchy:

### The Organizational Hierarchy
1. **Organization:** The root tenant (e.g., "Acme Corp"). Defines global policies, AI usage quotas, and overarching security constraints.
2. **Workspace:** A logical grouping of products within an Organization (e.g., "Acme Financial Services Workspace").
3. **Product:** The conceptual software being built (e.g., "Booking Automation"). It spans multiple repositories and architectures. Contains the Vision, Scope, Personas, and Business Goals.
4. **Release:** A major version iteration of the Product (e.g., "v2.0").
5. **Project:** A physical repository managed by Fénix that implements a part of the Product (e.g., `booking-api`, `booking-web`, `booking-iac`). It defines the language, framework, architectural patterns, and local standards.
6. **Sprint:** A timeboxed iteration targeting specific goals within a Project or Release.
7. **Epic:** A large, cross-cutting feature (e.g., "User Authentication System").
8. **Story:** A concrete user requirement (e.g., "As a user, I want to log in with Azure AD").
9. **Task:** The atomic unit of work generated by Fénix to fulfill a Story (e.g., "Generate AzureAD_Controller.go").

### The Execution Entities
Alongside the structural hierarchy, Fénix defines execution entities:
- **Workflow:** A macroscopic process definition (e.g., `Discovery`, `Release`, `Development`). Composed of `Phases`.
- **Phase:** A stage within a workflow containing `Task Groups`.
- **Task Group:** A collection of tasks that can be executed in parallel (e.g., `[Backend, Frontend, QA]`).
- **Task:** The absolute center of the execution model. Handled by the Scheduler.
- **Agent:** A behavioral persona defined by a mission, constraints, and contracts. Agents execute Tasks.
- **Skill:** A deterministic tool available to Agents (e.g., `GenerateController`, `RunTests`).
- **Artifact:** Any physical file (code, markdown, JSON) produced or consumed.
- **Engineering Knowledge Graph:** The semantic web linking all artifacts.

## Consequences
- **Positive:** By inverting Product and Project (`Product -> Project`), Fénix natively supports microservices architectures and monorepos seamlessly. It can orchestrate a feature that touches the API project, the Mobile project, and the IaC project simultaneously.
- **Negative:** The data model is significantly more complex and requires robust persistence (e.g., a real graph database or robust local indexer) to manage relationships across the entire hierarchy.
